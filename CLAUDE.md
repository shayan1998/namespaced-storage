# namespaced-storage

An npm package that puts a namespacing, typing and governance layer over key-value storage
(`localStorage`, `sessionStorage`, later cookies / IndexedDB / Redis).

## Read these first

- [.claude/docs/PLAN.md](.claude/docs/PLAN.md) — the master plan: problem, API, storage format,
  architecture, milestones, quality bar.
- [.claude/docs/DECISIONS.md](.claude/docs/DECISIONS.md) — ADR log: what was rejected and why.
- [.claude/docs/PREVIEW.md](.claude/docs/PREVIEW.md) — dry run of the 1.0 output, for critique.

**Before changing any design, update PLAN.md first, then add an ADR. Code follows the docs.**

## Non-negotiables

- `packages/core` has **zero runtime dependencies**.
- Every access to `window.localStorage` is inside `try/catch` — property access itself can throw
  `SecurityError` in a cookie-blocked iframe.
- Nothing may crash under SSR (no `window`).
- Reads never throw by default; writes throw, and `trySet()` exists for quota-sensitive paths.
- `clear()` is always namespace-scoped. Never call native `clear()`.
- The sync API stays synchronous. Async backends get a separate async surface (ADR-006).
- Keys beginning with `__nss` are reserved.
- **No central registry file.** Stores are declared co-located with their feature in
  `*.storage.ts`; the inventory is generated by `nss scan` (ADR-011).
- `defaults` (a plain object) is the primary typing path; `t.*` / Standard Schema is the advanced
  one for validation and defaultless keys (ADR-012).
- The package must be worth installing at level 1 (namespacing alone). Never make level 1 pay for
  level 2 or 3.

## Status

**M0 (scaffold) and M1 (namespacing core) are done** — `packages/core` at `0.1.0`, 64 tests,
99.5% line coverage, 2.09 kB. **M2 (codecs / smart envelope) is next.**

```bash
pnpm check   # typecheck + lint + test + build, everything CI runs
```

Known gaps deliberately left for later milestones: no envelope yet (plain JSON only), so no
`Date`/`Map`/`Set` round-trip, no TTL, no typing from `defaults`, no events, no namespace conflict
guard, no ESLint plugin, no CLI.
